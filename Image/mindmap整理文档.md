# Mindmap 整理文档（Image 文件夹）

> 说明：基于 `Image` 文件夹中的 mindmap 内容，整理为可读的文字版结构，便于评审与后续执行。

## 1. 核心主题
- **网页端横版游戏技术方案**

## 2. 目标与范围
- 面向浏览器（PC + 移动）
- 快速迭代与持续运营（活动、关卡、数值更新）
- 前期轻联网（排行榜、云存档），后期可扩展实时联机

## 3. 技术方案主干

### 3.1 客户端
- 引擎：Phaser 3
- 语言：TypeScript
- 构建：Vite
- UI：Phaser 原生 UI 为主，必要时配合 React

### 3.2 服务端与联网
- 起步：Supabase / Firebase（登录、存档、排行榜）
- 进阶：Node.js + NestJS（活动、经济系统、反作弊）
- 实时能力：Colyseus 或 Socket.IO（按需求引入）

### 3.3 资源与运维
- 资源：TexturePacker，Spine（可选）
- CDN：Cloudflare / 阿里云 CDN
- 监控：Sentry + PostHog / GA4
- 交付：GitHub Actions（自动构建、发布、回滚）

## 4. 架构分层
- 游戏逻辑层：状态机、关卡脚本、战斗规则
- 渲染输入层：Scene、Camera、Animation、Input
- 数据层：本地缓存 + 云端存档
- 配置层：远程 JSON（数值/活动开关，支持热更新）

## 5. 性能优化方向
- 首屏拆包（核心包 + 分包）
- 图像与音频压缩（WebP/AVIF）
- 对象池减少每帧创建
- 低端机降级策略（粒子/阴影/后处理可关闭）

## 6. 团队建议（最小可行）
- 客户端：2 人
- 技术美术/动效：1 人
- 后端：1 人（前期可兼职）
- 测试：1 人

## 7. 分阶段推进
- **P0（2~4 周）**：核心玩法 Demo + 资源规范 + CI/CD
- **P1（4~8 周）**：账号/存档/排行榜 + 新手流程 + 基础运营配置
- **P2（8~12 周）**：活动系统 + 热更新 + A/B 测试 + 视情况接入实时联机

## 8. 备选路线
- Cocos Creator（若团队已有经验）
- Unity WebGL（更复杂项目可考虑）
- PixiJS + 自研框架（不建议首版）

## 9. 结论
优先采用 **Phaser 3 + TypeScript + Vite + Supabase/Firebase** 的轻量组合，先验证核心玩法与运营闭环，再按数据决定架构升级。
